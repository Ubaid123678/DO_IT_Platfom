1. Project Overview

Do It is a global service marketplace that connects clients who need any task done with verified service providers. The platform supports both physical/local services (transport, cleaning, repairs) and digital/remote services (design, coding, writing). Providers are KYC-verified and rated; clients can post jobs, receive proposals, and pay securely through an in-app wallet with automatic currency conversion.

Core Value Proposition

  • Any service, anywhere in the world
  • Verified providers with KYC (Know Your Customer)
  • Escrow-based payments — money is only released when job is done
  • Automatic currency conversion (e.g. USD → PKR)
  • Dispute resolution with admin oversight
  • Fraud detection running in the background 24/7

Why This Stack?

MongoDB handles the flexible and varied nature of job types, service categories, and multilingual content without needing schema migrations. Redis provides sub-millisecond caching for location-based queries and job feed. Node.js + Express is lightweight and scales horizontally. Redis queues (via Bull) handle background jobs like fraud checks, currency conversion, and notification dispatch asynchronously.

3. User Roles & Registration Flow

3.1 Roles

  • Client — Posts jobs, pays for services, rates providers
  • Provider — Offers services, applies to jobs, receives payment
  • Admin — Manages disputes, reviews KYC, monitors platform

3.2 Registration Algorithm

STEP 1: User opens app
  → IP detected → language + currency set automatically
  → "Get Started" screen shown

STEP 2: Fill basic info
  → Full name, email, phone number, password
  → Role selection: CLIENT or PROVIDER
  → Country of residence

STEP 3: Email Verification
  → 6-digit OTP sent to email via SendGrid
  → OTP expires in 10 minutes
  → Max 3 attempts before 30-min cooldown
  → On success: email_verified = true

STEP 4: Phone Verification
  → 6-digit OTP sent via Twilio SMS
  → Same expiry + attempt rules
  → On success: phone_verified = true

STEP 5: Role-based redirect
  → IF role = CLIENT → navigate to Client Dashboard
  → IF role = PROVIDER → navigate to Provider Dashboard
     (limited access until KYC approved)

3.3 Provider KYC Flow

STEP 1: Provider sees banner "Verify to unlock all features"
STEP 2: KYC form submitted:
  → Government ID (front + back photo)
  → Selfie with ID
  → Proof of address (utility bill / bank statement)
  → Service category selection (can select multiple)
  → Service area: local radius OR remote (digital)

STEP 3: Admin reviews KYC documents in admin panel
  → APPROVED → kyc_status = "approved", full dashboard unlocked
  → REJECTED → kyc_status = "rejected", reason shown to provider, can resubmit

STEP 4: Provider sets up profile
  → Bio, skills, hourly rate or per-job rate
  → Portfolio / past work samples
  → Availability (calendar)

6. Job Lifecycle Algorithm

6.1 Job States

OPEN → IN_PROGRESS → COMPLETED → CLOSED
                 ↘ DISPUTED → RESOLVED (admin)
                 ↘ CANCELLED

6.2 Detailed State Machine

StateTriggerActions
OPENClient posts jobNotify nearby providers, visible in feed
IN_PROGRESSClient accepts proposalJob locked, other proposals declined, escrow funded
COMPLETEDProvider marks done + client confirmsPayment released to provider (minus platform fee)
DISPUTEDClient rejects completionJob frozen, admin notified, evidence from both parties
CANCELLEDEither party before in-progressRefund if payment made, penalty if after in-progress
CLOSEDCompleted + review submittedRating saved, job archived

6.3 Location-Based Job Matching Algorithm

WHEN client posts a physical job:
  1. Extract client's GPS coordinates from job post
  2. Query providers WHERE:
       - category IN job.categories
       - kyc_status = "approved"
       - location within job.radius km (MongoDB $geoNear)
       - is_available = true
       - rating >= 3.5 (minimum threshold)
  3. Sort results by: distance ASC, rating DESC
  4. Send push notification (FCM) to top 50 matching providers
  5. Job visible in their feed immediately

WHEN client posts a digital/remote job:
  1. Skip location filter
  2. Query by category + skills only
  3. Notify all matched providers globally
  4. Job visible in global feed

6.4 Dispute Resolution Algorithm

TRIGGER: Provider marks job complete → Client clicks "Not Complete"

STEP 1: Job moves to DISPUTED state
  → Both parties notified
  → Payment frozen in escrow

STEP 2: Evidence submission (48-hour window)
  → Provider uploads: photos, videos, chat history, GPS proof
  → Client uploads: evidence of non-completion

STEP 3: Admin review in admin panel
  → Admin sees both sides, full job history, chat logs
  → Admin decides: PROVIDER_WINS or CLIENT_WINS

STEP 4: Resolution
  → PROVIDER_WINS: escrow released to provider
  → CLIENT_WINS: escrow refunded to client wallet
  → Both parties notified with outcome and reason
  → Repeat disputes by same user → flagged for fraud review

7. Wallet & Payment System

7.1 Wallet Architecture

  • Every user (client + provider) has a wallet stored in MongoDB
  • Wallet holds a USD equivalent balance internally — display is converted to user's local currency
  • Escrow wallets hold funds during active jobs — separate from user wallets
  • Platform fee: configurable percentage (e.g. 10–15%) deducted before provider payout

7.2 Payment Flow

CLIENT SIDE:
  1. Client tops up wallet via Stripe (card / Apple Pay / Google Pay)
  2. Funds stored in client wallet (USD equivalent)

JOB ACCEPTED:
  3. Client confirms proposal → job budget locked in escrow wallet
     → client wallet balance decreases
     → escrow wallet balance increases

JOB COMPLETED:
  4. Provider marks complete → Client confirms
  5. Escrow wallet → platform fee deducted → remainder to provider wallet

PROVIDER PAYOUT:
  6. Provider requests withdrawal
  7. Wise API converts USD → provider's local currency (PKR, EUR, etc.)
  8. Transferred to provider's bank or mobile wallet

DISPUTE:
  9. Escrow remains frozen until admin resolves
  10. Then: either to provider or refund to client wallet

7.3 Transaction Record

Every money movement generates a Transaction document in MongoDB with: type, amount (USD), display_amount, display_currency, exchange_rate, from_wallet, to_wallet, job_id, status, and timestamp. This provides a full immutable audit trail.

8. Fraud Detection & Security

8.1 Background Fraud Detection System

A Bull (Redis-backed) job queue runs fraud checks asynchronously. Rules are evaluated after every significant event (registration, job post, payment, proposal submission).

FRAUD RULES ENGINE (runs in background via Bull queue):

Registration Fraud:
  - Same IP registered > 3 accounts in 24h → flag + manual review
  - Disposable email domain → auto-reject
  - Phone number reuse → alert admin

Payment Fraud:
  - Client tops up → immediately requests refund pattern → flag
  - Unusual payout amount (> 3x average for that provider) → hold + review
  - Multiple failed card attempts → temporary lock

Job Fraud:
  - Same client+provider pair completing > 5 jobs with no chat activity → fake job flag
  - Provider completing jobs in impossible locations (GPS spoofing check) → suspend
  - Review bombing (sudden influx of 5-star reviews for new provider) → hold reviews

Account Takeover:
  - Login from new country + large transaction → require 2FA re-verify
  - Password reset + immediate large withdrawal → block + email alert

IP Abuse:
  - VPN/proxy detected on financial transactions → require extra verification
  - Blocked country list enforcement

9. Multilingual & Multi-currency (IP Detection)

9.1 IP-Based Auto-Detection Algorithm

ON APP LAUNCH (first time or new session):
  1. Fetch user's IP address
  2. Query MaxMind GeoIP2 database:
     → Get country_code, country_name, timezone
  3. Map country_code to:
     → default_language (ISO 639-1 code)
     → default_currency (ISO 4217 code)
     → currency_symbol

  Examples:
  country_code = "PK" → language: "en", currency: "PKR", symbol: "₨"
  country_code = "US" → language: "en", currency: "USD", symbol: "$"
  country_code = "DE" → language: "de", currency: "EUR", symbol: "€"
  country_code = "SA" → language: "ar", currency: "SAR", symbol: "﷼"
  country_code = "IN" → language: "hi" or "en", currency: "INR", symbol: "₹"

  4. Store in user profile + local device storage
  5. User can override anytime in Settings

9.2 Supported Languages (Phase 1)

  • English (default fallback for all regions)
  • Urdu (Pakistan)
  • Arabic (Saudi Arabia, UAE, Egypt)
  • Hindi (India)
  • Spanish (Latin America, Spain)
  • French (France, West Africa)
  • German (Germany, Austria, Switzerland)
  • Turkish (Turkey)

9.3 Currency Conversion

All internal storage is in USD. Displayed amounts are converted in real-time using exchange rates fetched every 30 minutes from a forex API (e.g. Open Exchange Rates) and cached in Redis. Actual payouts use the Wise API for real mid-market rates.
